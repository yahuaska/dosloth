# План: единая таблица прерываний из вызываемых объектов

## Зачем
Сейчас `INT n` вызывает Python-функцию из `cpu.int_handlers`, а `INT 21h AH=25h/35h` пишет и читает байты по `0000:n*4`, и эти записи ни на что не влияют. Нужно, чтобы:
- программа могла поставить свой обработчик (`AH=25h`), и `INT n` реально прыгал в её код;
- Python-обработчики и код программы лежали в одной таблице и вызывались одинаково.

## Идея (вариант A)
Одна таблица `cpu.vectors: n -> callable(cpu)`. `INT n` всегда делает `vectors[n](cpu)`.
- Python-обработчик: обычная функция, как `int21`.
- Код программы: объект `GuestHandler(seg, off)` с `__call__`, который делает то, что делает настоящий `INT`: кладёт в стек флаги, CS, IP, сбрасывает IF/TF и прыгает на `seg:off`.

## Шаги (по одному, каждый запускает на одну программу больше)
1. **`IRET` (`CF`)**: достать из стека IP, CS, флаги. Без него вернуться из обработчика программы нельзя.
2. **`GuestHandler`** и переименование `int_handlers` в `vectors` (функции из `dos.py` остаются как есть).
3. **`AH=25h`** кладёт в таблицу `GuestHandler(DS, DX)`.
4. **`AH=35h`**: для `GuestHandler` вернуть его `seg:off`. Для Python-обработчика пока вернуть `0000:0000`.
5. **`PUSHF`/`POPF` (`9C`/`9D`)**: нужны, когда программа вызывает старый обработчик как `pushf` + `call far`.

Брать шаги по мере того, как их требует очередная программа (сейчас `esetup.exe` только сохраняет вектор INT 0).

## Что решить, когда понадобится
- **Два источника правды.** Таблица-словарь и байты по `0000:n*4` расходятся. Если программа читает таблицу напрямую (`les bx,[0:n*4]`), она ничего не увидит. Тогда переходим на вариант B.
- **Цепочка к Python-обработчику.** Если программа получила адрес через `AH=35h` и вызывает его (`call far`), нужен адрес, на котором `step()` вызовет Python-функцию. Варианты: фиктивные адреса `F000:nn` и проверка в `step()`, либо заглушки в памяти из особого опкода `PYCALL n` + `IRET`.

## Вариант B (если A упрётся)
Таблица в памяти по `0000:n*4` — единственная правда, как в железе. `INT n` читает её и прыгает. Python-обработчики прячутся за заглушками в памяти (`PYCALL n; IRET`), а в таблице лежит адрес заглушки. Тогда `AH=35h` всегда возвращает настоящий адрес, а `GuestHandler` не нужен.

## Не делаем
Аппаратные прерывания (таймер, клавиатура), IF/TF как настоящие флаги, пока ни одна программа их не требует.

# План: конфиг окружения и файловая система (записано 2026-10-13)

## Зачем
`esetup.exe` дошёл до файловых функций (`INT 21h AH=43h`, перед этим `3Eh`) и до перебора дисков (`0Eh`, `19h`, `44h/08h`). Диски и их свойства сейчас зашиты константами в `dos.py` (`DRIVES`, `REMOVABLE_DRIVES`, `DEFAULT_DRIVE`). Нужен конфиг, который описывает диски и связывает их с каталогами хоста, чтобы программа видела настоящие файлы.

## Принятые решения
1. **Формат: TOML** (`tomllib` из стандартной библиотеки, Python 3.12). Правило «только stdlib» не нарушается.
2. **Относительные `path` считаются от каталога конфига**, а не от каталога запуска.
3. **`path` и носитель.** Диск без `path` (или с пустой строкой) = носителя нет, как пустой дисковод. Это допустимо только для сменных (`removable = true`). Несменный диск без `path` — **ошибка при разборе конфига**. (В TOML нет `null`, поэтому «пусто» = ключа нет.)
4. **Ключ `-c ФАЙЛ`** передаёт конфиг. Без него работают встроенные значения (то, что сейчас в константах), поведение не меняется.
5. **Регистронезависимый поиск файлов.** DOS не различает регистр, Linux различает; пути из программы переводятся в пути хоста по компонентам с поиском без учёта регистра.

## Формат (пример)
```toml
default = "C"           # необязательно: с какого диска стартует программа

[disks.A]
removable = true       # нет path: дисковод без дискеты

[disks.B]
removable = true

[disks.C]
path = "."             # от каталога конфига
removable = false

[disks.D]
path = "/tmp"          # смонтированный носитель
removable = true
```
(Файл `samples/config.yaml` — набросок в YAML; переписать как `config.toml`.)

## Правила разбора (любая ошибка: понятное сообщение и выход, без запуска)
- имя диска — одна латинская буква (регистр не важен), хранится заглавной;
- `removable` обязателен (bool);
- `path`: строка; у несменного обязателен; если указан, каталог должен существовать (опечатка не должна тихо превращаться в «диска нет»);
- `default` (если есть) — буква существующего диска; без него: `C`, если есть, иначе первый несменный, иначе первый;
- неизвестные ключи — ошибка (ловит опечатки);
- хотя бы один диск.

## Что меняется в коде
- **`mydos/config.py`** (новый): `load(path)` → `Config` (диски по номерам с буквой, `removable`, корнем на хосте; `default_drive`) и встроенная `DEFAULT`.
- **`mydos/dos.py`**: `DRIVES`, `REMOVABLE_DRIVES`, `DEFAULT_DRIVE` берутся из `Config`; `install(cpu, config)`. `AH=0Eh` возвращает «наибольший номер диска + 1» (в конфиге могут быть пропуски).
- **`mydos/__main__.py`**: ключ `-c`.
- **`AGENTS.md`**: описание конфига; в `.gitignore` проверить, что `samples/` не мешает (конфиг в нём не попадает в репозиторий; пример положить в корень как `config.example.toml`).
- Тесты на разбор: правильные конфиги, каждое правило ошибки, относительные пути, значения по умолчанию.

## Дальше: файловая система (отдельные шаги)
- **Перевод путей** `(диск, путь DOS, текущий каталог диска)` → путь хоста: `\` и `/`, `.` и `..` (выше корня диска нельзя подняться), поиск каждого компонента без учёта регистра через `os.listdir`. Имена не в формате 8.3 пока скрыты от программы. Что делать, если `a.txt` и `A.TXT` лежат рядом, решить, когда встретится.
- **Текущий каталог для каждого диска** — состояние в `DosState`.
- **Диск без носителя** → ошибка 15h (диск не готов) на любой файловой операции.
- **Порядок функций:** `43h` (атрибуты, как `os.stat`), `3Dh` открыть, `3Fh` читать, `42h` перемотка, `3Ch` создать, `40h` запись в файл, `4Eh/4Fh` поиск, `47h`/`3Bh` каталоги, `36h` свободное место, `1Ah` DTA.
- **Окружение программы:** имя программы в блоке окружения строить через таблицу дисков (`samples/esetup.exe` → `C:\ESETUP.EXE`), а не склеивать из имени файла.

## Открытое
- Ключ `readonly` для сменного носителя «CD-ROM» (по умолчанию `false`; добавить, когда понадобится).
- Ключ `type` (`floppy`, `hdd`, `cdrom`) вместо булева `removable`, если типы начнут вести себя по-разному (например, `IOCTL 4409`).
- Что делать с длинными именами хоста: скрывать или сокращать до `ИМЯ~1`.
